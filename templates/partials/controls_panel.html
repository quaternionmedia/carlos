{# The options drawer, its device palette, the example picker and the row controls all lived here. They are gone: menus are the radial menu, per rad's interaction contract, and a second menu system would be a second answer to a question the contract already settles. See docs/rad-integration.md. What is left is tuned to one job: saying what is on screen. A status bar was pinned across the top of the window and this floated over the rack, so the two halves of that answer were in two places — the running commentary up there, the persistent facts down here — and the bar took a slice off the top of every rack whether or not it had anything to say. One panel now, and it reads top to bottom: what this rack is, what is in it, which way it faces, and what just happened. It still holds the two controls a ring cannot express — a patch name is a text field, a file input is a file input — and it resolves no context and emits no intent, which is what a menu is. `palette` here is rad's word for a set of colour tokens, and that is what this is built from: no colour below is a literal. #}
